# ShipDamageModule — breakdowns, breaches and repair

Module breakdowns, hull breaches, the leak and their repair (the mechanic's job). Read the [root AGENTS.md](../../../../AGENTS.md) first (game, rules, module map). Change this module's description here, not in the root file.

## Assembly
`Features.ShipDamageModule` (layer 5; references: Ship, DebugModule.Contracts, GameCoreModule.Contracts, Grab, NetworkModel, Mirror, Zenject): module breakdowns, breaches, the leak and their repair. The ship core is [ShipModule](../ShipModule/AGENTS.md).

## Loop status
- **module breakdowns and hull breaches (the mechanic's job):** a rock impact may break the installed module nearest to
  the hit and open a breach at the nearest free hull damage point (see "Ship damage and repair" in Key places below). A broken
  module stays installed but does not work (its stat modifiers are suspended, a broken turret does not fire); an open
  breach leaks hull HP in flight. A player repairs a module with the **wrench** and a breach with the **hammer** by
  holding the interact key on it; both tools lie on the rack on the deck at the start of a run and are sold in the shop.
  Everything is repaired for free on landing (with the hull, `RepairOnLanding`);

The candidates come from `IShipDamageCandidateSource` (`ShipDamageCandidateSource`: the installed modules by socket, breakable while `CanBreak` and working, and the hull damage points, free while closed), which also tells the gnawing bugs ([BugModule](../BugModule/AGENTS.md)) where to land; a bug's bite is a weak `ServerApplyImpact` (strength 0.05) through the same rule plus hull HP with cause `ShipDamageCause.Gnaw`. `ShipHullLeakSystem` leaks `LeakHullPerSecond` per open breach in flight through `IShipHull` (cause `HullLeak`), gathered and dealt in steps of `LeakStepHull` by the pure `ShipHullLeakRule`. Numbers in `ShipDamageConfiguration_Default` (Addressables, `ShipDamageConfigurationValidator`); the helm has `CanBreak` off. **Places on the ship (`ShipPlatform`):** 11 `ShipHullDamagePoint`s around the deck edges under `HullDamagePoints` (one NetworkIdentity; ids `breach-01..11`; each point adds itself to the `ComponentRegistry<ShipHullDamagePoint>`, read as `IReadOnlyComponentRegistry<ShipHullDamagePoint>`), each with a dent look, a red outline and `ShipBreachRepairInteractable` (its trigger is on only while the breach is open; both repair places share `ShipRepairInteractableBase`: the tool kind, the hold seconds and the repair volume); every socket has `ShipModuleRepairInteractable` with a `RepairVolume` trigger over the module, on only while it is broken (slot views have no colliders and the engine socket plates sit in the deck), and `ShipSocketDamageView`; the look is `ShipDamageVisual` (`GameResources/Effects/ShipDamageEffects.prefab`: smoke + sparks while damaged, a flash on repair, on every peer; the module effects live under `ModuleDamageEffects`, outside the sockets, so the socket outline does not paint them). **Tools:** a tool is one `RepairToolDefinition` (`GameResources/Repair/WrenchTool`, `HammerTool`: id, name, price, item prefab, what it repairs (`ShipRepairKind` Module / Breach), speed: repair seconds = `RepairSeconds` / speed); items `WrenchItem` / `HammerItem` (`Grabbable` + `RepairTool`, registered in the network manager's spawn prefabs); `ShipToolRack` on the deck stocks one of each at the run start (`ShipRunService.Bind` -> `IShipRunStartListener` -> `ShipToolRackStockService` over the `ComponentRegistry<ShipToolRack>` every enabled rack joins; made under the rack so they stay in the game scene; `ConnectionSceneObjectIds` gives no scene id to an object the server already spawned, or a client would look for these tools in its scene); the shop sells them after the modules (`ShopCatalog.Tools`). **Hold to use** is general Grab code: an `InteractableBase` that returns `TryGetHoldSeconds` is used by holding interact: `UseController.CmdBeginHold` / `CmdEndHold`, the server runs `HoldUseProgress` (pure) and cancels it when the target stops being usable, the player leaves reach or another item is in the hand, then calls `ServerUse`; `CmdUse` refuses hold targets. The client ends the hold on key release (`Grab.Canceled`) or when the crosshair leaves the target; the progress is a SyncVar on `UseController` -> the local `HoldUseModel` -> the HUD bar. The progress is not kept across a reconnect. Tooltips: `Tooltip_ModuleBroken` / `Tooltip_ModuleRepairReady`, `Tooltip_Breach` / `Tooltip_BreachRepairReady`, `Tooltip_Wrench` / `Tooltip_Hammer`; `ShipModuleRepairTooltipProvider` shows "Broken: needs a wrench" on any tooltip of a broken module's socket. **HUD:** `ShipConditionView` / `ShipConditionPresenter` in `LobbyModule` under the hull bar: hull, a tile per installed module (`ModuleDefinition.Icon`, its name while it has none; green, red when broken, blinking when it just broke: `ShipHullHudConfiguration.BrokenBlinkSeconds`) and the open breaches; `HoldUseProgressView` under the crosshair. Debug: the debug window's Ship → "Break a module + open a breach" on the host breaks a random working module and opens a random free breach (`ShipDamageModule/Scripts/Debug/`: `ShipDamageDebugSystem`, `IShipDamageDebug`) |

The ship's broken modules and open breaches are the shared `ShipCondition` model (see "Ship damage and repair" above).
