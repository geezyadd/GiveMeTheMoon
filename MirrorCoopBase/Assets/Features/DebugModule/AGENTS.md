# DebugModule — the in-game debug window

The debug window and the debug action registry. Read the [root AGENTS.md](../../../../AGENTS.md) first (game, rules, module map). Change this module's description here, not in the root file.

## Assembly
- `Features.DebugModule.Contracts` (layer 1; no references): `DebugModule/Contracts/`: `IDebugActionRegistry`, `DebugActionDefinition`, `DebugActionValue`, `DebugSections`, `DebugActionReasons`; the ship, the flight field, the player life and the shop register their debug actions through it.
- `Features.DebugModule` (layer 3; references: DebugModule.Contracts, Mvp, Camera, GameFlow, Input, Zenject, UnityEngine.UI): the debug window; compiled only in editor / development builds through its asmdef's define constraint `UNITY_EDITOR || DEVELOPMENT_BUILD`, so GameCore installs it inside the same `#if`.

## Key places
| What | Where |
|---|---|
| Debug window | `Assets/Features/DebugModule/` (editor / development builds only, the whole assembly). A small see-through **DEBUG** button in the bottom-right corner of the game HUD (`DebugWindow`, prefab `GameResources/Prefabs/DebugWindow.prefab`, Addressables group `Windows`, opened by `DebugWindowSystem` for the whole session) opens and closes the debug panel; the panel frees the cursor while it is open (`CursorModel`; walking stays on, a seated gunner's turret ignores the mouse as with any free cursor). **Tab** frees the cursor to reach the button, **Esc** or the button closes the panel. The panel lists the registered actions by section in the order the sections were first registered (Ship, Rocks, Weapons, Player, Shop, View, Agents): a button with a clear label, a number field for an action with a value (the hull hit's damage), a hover hint with the description, and a greyed-out button with the reason next to it when the action cannot run now (host only, not in flight, no local player...; `DebugActionAvailabilitySystem` asks every action each frame while the panel is open, `DebugActionsModel` tells the panel only changes). Register an action: inject `IDebugActionRegistry`, call `Register(new DebugActionDefinition(section, label, description, readUnavailableReason, run))` in `Initialize` and dispose the returned handle in `Dispose`; the class and its binding stay inside `#if UNITY_EDITOR \|\| DEVELOPMENT_BUILD` (a release build has no registry, no button, no window). Actions now: Ship → "Hit the hull" (damage, default `ShipHullConfiguration.DebugDamage`), "Destroy the hull (hull = 0)", "Break a module + open a breach", "Throttle = N" (0 = Stop, 1 = Full, default 1; at a station past the launch mark it takes off; host with a ship, `ShipThrottleDebugSystem`), "Show station: off / on" (any player, local: this peer's own marker of the next station in flight, `SonarStationMarkerDebugSystem` in SonarModule); Rocks → "Aim at the nearest small rock", "Aim at the nearest large rock" (in flight), "Break the nearest rock", "Drop ore before the ship" (`FieldOreDropDebugSystem` in FlightFieldModule), "Show impact volume: off / on" (any player, local, `ShipImpactVolumeDebugSystem` in ShipImpactModule); Weapons → "Spawn the weapon test dummy", "Remove the weapon test dummy"; Player → "Kill me" (any player), "Toggle dead / alive (stand-in life)" (only with the fallback `DebugPlayerLifeQuery`); Shop → "Open the shop here" (`ShopDebugOpenSystem`, the former **L** key, any player), "+1000" (`ShopDebugMoneySystem`, any player: the server adds `WalletConfiguration.DebugGrantAmount` to the crew wallet); View → "Haze: on / off", "Haze clear distance" (metres; any player, local: this peer's own view, `SpaceHazeDebugSystem` in SpaceHazeModule). Agents → "Spawn test agents (N)" (default 20), "Remove all field agents", "Land an agent on the deck" (host with a ship, FieldAgentModule). The Ship (except "Show station"), Rocks and Weapons actions are host only. |
