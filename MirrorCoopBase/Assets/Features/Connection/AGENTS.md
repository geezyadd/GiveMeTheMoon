# Connection — joining a running session

Connection, authentication and the join rule. Read the [root AGENTS.md](../../../../AGENTS.md) first (game, rules, module map). Change this module's description here, not in the root file.

## Key places
| What | Where |
|---|---|
| Joining a running session | `Connection/Scripts/Game.Connection/Join/`: `JoinRule` (pure: lobby or `RunJoinWindow.AtStation`, free slot out of `ConnectionConfig.MaxConnections`, version, Steam id; reasons `InFlight` / `ServerFull` / `MapChanging`), `ConnectionJoinPolicy` (the rule on the live session, used by `ConnectionAuthenticator` once at authentication; `OnJoinStateChanged` is the one event for "an input of the rule changed": run window, map change, players), `SteamLobbyJoinableSystem` (Steam lobby joinable exactly when the rule lets a new player in), `ConnectionRejectModel` + `ConnectionRejectMessages` (the reason shown in the menu; `SessionDroppedMenuSystem` in GameCore switches a client whose session ended without its own Leave to the menu state: a turned-away join, the host quitting, a lost connection; `ConnectionNetworkEvents.SessionDropped` is raised by `ConnectionNetworkManager.StopSessionAndReturnToMenu`, the entry of those network callbacks, once the menu scene is back). Connection reads the run only through the contracts `ISessionJoinGate` (`ShipRunJoinGate`) and `ISessionJoinSpawn` (`ShipDeckJoinSpawn`, the next `IShipDeckSpawnPoints` pose) in `GameCoreModule.Contracts`. A mid-run joiner loads the map through Mirror's scene message and reports `MapLoadedMessage`; `ConnectionLateJoin` makes its player only then, on the deck. The transport allows one connection over the slots so an extra player hears "the crew is full" |
| Simulated lag (editor and development builds) | `ConnectionLatencySimulation` puts `ConnectionLagTransport` (on a child object of the network manager) between the manager and the chosen transport, in `Awake` and on every transport switch; it starts with no delay and no loss. Our own wrapper instead of Mirror's `LatencySimulation`: there the jitter drifts slowly (Perlin noise), which Mirror's snapshot buffer absorbs, and fast jitter would reorder reliable messages. `ConnectionLagQueue` draws the jitter per message (unreliable messages may overtake each other), drops lost unreliable messages and delivers a lost reliable one a round trip later, holding back the reliable ones behind it. The debug window's Network section has a "Lag: ..." button (`ConnectionLatencyDebugSystem`) that cycles through `ConnectionConfig.LatencyProfiles` (off; 80 ms; 150 ms + 5 % loss; 150 ms with 100 ms spiky jitter, like a far-away player; 300 ms + 10 % loss). It delays only what this process sends: set it on the client to make that client's data reach the host late, on both for a full round trip. Release builds have neither |
